# Security Testing Hub

> 🇰🇿 Қазақша нұсқа: жалпы құжаттама әзірге жоқ, бірақ шабуылдарды тестілеу
> нұсқаулығы бар — [attack-playbook.kk.md](attack-playbook.kk.md).

Открытый SAST-сканер для тех, кто пишет Node.js/Express-приложения быстро,
часто с помощью AI-ассистентов ("vibe coding"), и не всегда успевает
проверить каждую строчку на классические уязвимости.

## Зачем это нужно

AI-ассистенты быстро генерируют рабочий код, но часто воспроизводят одни и
те же уязвимости внедрения (SQL-запросы через конкатенацию строк,
неэкранированный вывод в HTTP-ответ, `exec()` с подставленным вводом) —
просто потому что такие паттерны часто встречаются в обучающих данных.
Этот инструмент — быстрая локальная проверка (pre-commit/CI), заточенная
именно под паттерны, которые чаще всего появляются в "вайбкодинговых"
Express-приложениях.

## Что находит (v1 / MVP)

| Уязвимость | CWE | Как ищем |
|---|---|---|
| SQL Injection | CWE-89 | taint-анализ вызовов `db.query`/`execute`/`knex.raw` |
| XSS (отражённый) | CWE-79 | taint-анализ `res.send`/`write`/`end` |
| Command Injection | CWE-78 | taint-анализ `child_process.exec`/`execSync` |
| Path Traversal | CWE-22 | taint-анализ вызовов `fs.*` |
| SSRF | CWE-918 | taint-анализ `fetch`/`axios`/`http(s)`/`request`/`got` |
| CSRF | CWE-352 | эвристика по роутам (нет проверки токена) |
| IDOR | CWE-639 | эвристика по роутам (id-параметр без проверки владения) |
| Broken Access Control | OWASP A01:2021 | эвристика по роутам (admin-путь без проверки роли) |
| Insecure Role Assignment | CWE-639 | паттерн (роль читается из клиентских данных) |
| Insecure File Upload | CWE-434 | паттерн (фильтр загрузки доверяет только Content-Type) |
| Username Enumeration | CWE-203 | паттерн (разные сообщения об ошибке логина) |

Подробный разбор всех 15 классов атак (что это, как проверить руками,
как защититься) — в [attack-playbook.ru.md](attack-playbook.ru.md).

## Как это работает

1. **Парсинг** — каждый `.js`/`.jsx`/`.ts`/`.tsx` файл парсится в настоящий
   AST через Tree-sitter (не регулярки).
2. **Taint-анализ** — для пяти правил, основанных на потоке данных,
   анализатор находит "источники" (`req.params`, `req.query`, `req.body`, ...),
   отслеживает их через локальные переменные и интерполяцию в
   template-строках **внутри одной функции** (intra-procedural — см. ниже),
   и проверяет, попадает ли tainted-значение в опасный "sink"
   (`db.query`, `res.send`, `exec`, `fs.readFile`, ...).
3. **Отчёт** — результат в виде цветного текста в терминале, JSON или
   SARIF (для GitHub code scanning).

## Ограничения (честно, как в плане разработки)

- **Только JavaScript/TypeScript.** Python и PHP — после MVP.
- **Intra-procedural taint-анализ.** Если tainted-значение проходит через
  вспомогательную функцию (`sanitize(req.params.id)`), эта версия это
  пока не отследит — inter-procedural анализ запланирован на v2.
- **Целевой False Positive Rate: 25–30%**, False Negative Rate: <10%. Для
  сравнения: у Snyk ~15–20% FP, у SonarQube ~20–30% FP — результат
  v1-инструмента соло-разработчика в этом диапазоне честен, а не является багом.
- **CSRF-проверка эвристическая**, не taint-based: помечает
  state-changing роуты (`POST`/`PUT`/`DELETE`/`PATCH`) в файлах без
  видимой CSRF-защиты. Предполагает cookie/session-аутентификацию.
